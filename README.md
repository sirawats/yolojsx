# yolo-jsx

Build one JSX component into a deployable React application—without setting up a frontend project first.

`yolo-jsx` supplies React, Vite, Tailwind CSS, and Ant Design, generates the application shell, and writes either a static `dist/` directory or one portable compressed HTML file.

## Requirements

- Node.js `^20.19.0` or `>=22.12.0`
- A `.jsx` file that default-exports a React component

## Install and run

Install globally:

```sh
npm install --global yolo-jsx
yolojsx Home.jsx
```

Or run without a global installation:

```sh
npx yolo-jsx Home.jsx
```

Both `yolojsx` and `yolo-jsx` are installed as executable names.

## Component contract

The entry must be a readable `.jsx` module with a default-exported React component:

```jsx
import { Button } from "antd";

export default function Home() {
  return (
    <main className="min-h-screen bg-slate-100 p-8">
      <Button type="primary">Ship it</Button>
    </main>
  );
}
```

Running:

```sh
yolojsx Home.jsx
```

produces:

```text
dist/
├── .yolojsx-output.json
├── index.html
└── assets/
    ├── index-*.css
    └── index-*.js
```

The default public base is `./`, so the directory can be hosted below an arbitrary URL path.

## Single compressed HTML

Build and package directly. The default filename comes from the JSX entry basename and is written in the invocation directory:

```sh
yolojsx Home.jsx --single-file
# Home.html
```

Choose an explicit file instead:

```sh
yolojsx Home.jsx --single-file --output index.html
```

Or package an existing compatible build without changing that directory:

```sh
yolojsx pack dist --output index.html
```

The resulting HTML contains a small uncompressed loader and a base64-encoded gzip application payload. When opened, including through `file://`, a modern browser uses its native `DecompressionStream("gzip")` implementation to restore the application. No adjacent asset directory or web server is required.

The packer supports the controlled output shape generated by `yolo-jsx`: one HTML entry, one executable JavaScript bundle, ordered stylesheets, and convertible local assets. It rejects extra executable chunks, workers, service workers, runtime-loaded WASM, unresolved local files, and runtime-relative `fetch()` calls rather than creating an incomplete artifact.

## CLI options

```text
Usage: yolojsx <entry.jsx> [options]
       yolojsx pack <directory> --output <file.html> [options]

Options:
  -o, --out-dir <path>  Output directory (default: ./dist)
      --base <path>     Public base path (default: ./)
      --single-file     Create one compressed HTML file
      --output <path>   Single HTML output path
      --force           Replace an existing protected output
  -h, --help            Show help
  -v, --version         Show the installed version
```

Paths are resolved from the directory where the command is invoked:

```sh
yolojsx pages/Home.jsx --out-dir public/app --base /application/
```

`--output` is valid for `--single-file` builds and is required by `pack`. Single-file mode cannot be combined with `--out-dir` or `--base` because it has no external asset base.

## Supplied stack and imports

The CLI supplies and deduplicates these packages, so they do not need to be installed beside the JSX file:

- `react`
- `react-dom`
- `antd`
- Tailwind CSS build support

Relative imports stay relative to the original source file:

```jsx
import Header from "./components/Header.jsx";
```

Other bare packages resolve from the input project's own `node_modules`. Install those dependencies in the input project as usual. `@ant-design/icons` is not currently part of the guaranteed stack.

## Tailwind CSS and Ant Design

Tailwind source detection covers the entry file's directory and nested local source files. Tailwind's theme, preflight, components, and utility layers are compiled into the generated static stylesheet.

That stylesheet loads before the application JavaScript. Ant Design then injects its component styles at runtime through its CSS-in-JS system. This ordering keeps Tailwind utilities available while allowing Ant Design's component styles to be applied during rendering.

Because Tailwind preflight is enabled, global element defaults follow Tailwind's reset. Apply explicit utilities when a plain element needs different styling.

## Safe output replacement

A successful build writes `.yolojsx-output.json` to identify managed output. When any selected output directory already exists, the CLI asks `Replace it? Type yes or no:` before building. Type `yes` to authorize that replacement or `no` to leave it unchanged.

The same prompt protects non-empty directories without a valid marker, with an additional unowned-output warning. Filesystem roots, the current working directory, and directories containing the source entry are always rejected.

Builds are staged separately. If compilation fails, the last successful managed output remains intact.

Single-file output follows the same conservative approach: an existing `.html` file prompts for `yes` or `no`, directories and symbolic links are never replaced, and publication occurs through a staged sibling file. `pack` rejects an output inside its input directory and treats every input file as read-only.

Use `--force` to explicitly replace an existing valid target without prompting. In a non-interactive session the CLI never waits for input: it refuses an existing target and directs automation to use `--force`.

## Browser and security notes

Single-file artifacts require a browser with native `DecompressionStream` gzip support. Unsupported browsers and corrupt payloads display a readable loading error. The loader and restored application execute inline code, so the artifact is not compatible with embedding contexts that enforce a strict Content Security Policy without allowing inline scripts and styles. Inputs and packed builds are trusted local code; compression is not a security boundary.

## Current limitations

- JSX only; TSX and type checking are not included.
- One page and one default-exported component per invocation.
- No development server, watch mode, SSR, or library-mode output.
- No custom Vite configuration or HTML template.
- No automatic `public/` directory copying.
- Inputs are trusted local code; the build is not a security sandbox.
- Single-file mode does not support multi-chunk applications, workers, service workers, runtime-loaded WASM, or runtime-relative resources.

## Example

The repository includes [examples/Home.jsx](examples/Home.jsx), which combines Tailwind utilities and Ant Design components:

```sh
npm install
node bin/yolojsx.js examples/Home.jsx
```

## Development

```sh
npm install
npm run verify
```

`npm run verify` runs tests, syntax checks, the npm package-content preview, and a packed-artifact smoke test covering directory output, both single-file forms, `pack`, overwrite refusal, and `--force`. The package smoke test extracts the tarball into a temporary directory and links the repository's existing `node_modules`, so normal development does not reinstall dependencies.

Use `npm test` for the fastest behavior-only loop, `npm run check` for syntax checks, or `npm run verify:package` for only the packaged-artifact smoke test. A genuine isolated `npm install` is intentionally reserved for the pre-release checklist.

See [RELEASING.md](RELEASING.md) for the pre-release checklist.
